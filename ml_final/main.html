The Journey - From Regression to Classification

Initial Approach: CLTV Regression ❌

Problem: Tried to predict Customer Lifetime Value (continuous).

Results:

  • Best R² = 0.1589 (only 15.89% variance explained)
  • Tested 7 different strategies - ALL FAILED
  • Log transformation made it worse (R² = 0.11)

Why Regression Failed

  • Extreme Target Variance: CLTV range 25k-720k (29x spread)
  • Insufficient Features: Only 10 features for continuous prediction
  • Overfitting Signal: Train R² = 0.72 vs Test R² = 0.11 (61% gap impossible to close)
  • Data Leakage Proof: With target-derived feature, R² = 0.84 (but that's cheating!)

Seven Strategies - All Tested, All Failed

  • Would need: Employment history, education, financial data
  • Missing critical information about income drivers

Final Model Selection & Justification

Final Configuration

GradientBoostingClassifier(
    n_estimators=200,        # 200 trees for stability
    learning_rate=0.1,       # Standard learning rate
    max_depth=8,             # Deeper trees for patterns
    subsample=0.9,           # 90% sampling for robustness
    min_samples_split=5,     # Prevent overfitting
    min_samples_leaf=2,      # Reasonable leaf size
    class_weight='balanced', # Handle imbalance
    random_state=42          # Reproducibility
)

Why NOT Other Models?

  • Logistic Regression: Too simple, can't capture non-linear patterns (60%)
  • Decision Tree: Overfits directly to training data (59%)
  • KNN: Requires distance sensitivity, struggles with scaling (53%)
  • Random Forest: Good, but Gradient Boosting edges out with tuning (59.8% vs 60.2%)

Limitations

Technical Limitations

MAJOR

1. Class Imbalance

  • • 125:1 ratio between largest & smallest
  • • Minority classes nearly impossible to learn
  • • Would need: 10x more samples or separate models

2. Feature Limitations

  • • Only 9 features available
  • • Income is determined by: employment, education, financial history
  • • Missing: Job sector, savings, loans, etc.

3. Feature-Target Mismatch

  • • Insurance behavior is a proxy indicator
  • • Real income drivers not in dataset
  • • Features explain only surface patterns

4. Accuracy Not Production-Ready

  • • 60.2% sufficient for pilot/research
  • • Production deployment requires >85% accuracy
  • • Need major feature engineering/data collection

Recommendations for Improvement

Short-term (Quick Wins)

Apply SMOTE

Oversample minority classes. Could improve recall on Class 0 by 20-30%.

Threshold Tuning

Adjust decision boundaries per class. Trade off precision vs recall based on business goals.

Cost-Sensitive Learning

Higher penalty for missing low-income customers. Force model to focus on minorities.

Long-term (Structural Changes)

1

Collect Additional Features

Employment sector, job title, detailed education, financial metrics, transaction patterns.

Expected impact: +15-20% accuracy
2

Separate Models per Class

Build binary classifiers for each income level and combine predictions.

Expected impact: +10-15% minority class recall
3

Ensemble with Domain Models

Combine ML with rule-based models for low income. Hybrid approach for better coverage.

Lessons Learned

What Worked

  • Systematic Approach: Tested all obvious strategies thoroughly, documented failures, made data-driven decision to pivot.
  • Honest Assessment: Admitted regression fundamentally limited, didn't force-fit bad approach.
  • Model Stability: CV std = 0.002 (excellent stability), no overfitting, reproducible (rs=42).

What Didn't Work

  • ❌ Regression on CLTV: Mathematical ceiling at R² = 0.16
  • ❌ Data Curation: All 7 strategies made things worse
  • ❌ Log Transform: Helped overfitting but hurt overall R²
  • ❌ Feature Engineering: No improvement without target leakage

Key Insight

"The best model is not always the model with the highest metric. You must justify the final choice logically."

Started with wrong task (regression) → Switched to right task (classification) with justification → Achieved stable, defensible solution.

Questions & Discussion

Q: Why Classification over Regression?

Regression proved mathematically limited (R² glass ceiling at 0.16). 7 different strategies all failed. Classification better aligned to available features.

Q: Why Gradient Boosting?

Best accuracy (60.2%) among 5 tested algorithms. Handles class imbalance effectively. Stable cross-validation scores.

Q: What about 60.2% accuracy?

Not production-ready alone, but good enough for pilot/research. Provides baseline for future improvements. Clear path to 80%+ with better features.

Q: Why not 85%+ accuracy?

Insufficient features (9 only, missing employment/financial data). Extreme class imbalance (125:1). Would need different data or separate models.
